# RenCrow 音声パイプライン仕様

## 1. 目的

ブラウザからマイク入力を受け、**音声認識（ASR）** と将来的に **音声合成（TTS）** を HTTP ベースのサービスへオフロードする。  
UI と中継（voice-bridge）は Node.js、認識は **Whisper（whisper.cpp サーバー）**、合成は **Style-Bert-VITS2（SBV2）** を想定する。

---

## 2. 構成要素

| コンポーネント | 役割 | ポート |
|----------------|------|--------|
| **voice-bridge** | 静的 UI 配信、WebSocket でブラウザと双方向、Whisper へ HTTP プロキシ、**サーバーサイド VAD** | **8090**（HTTP, `server.js`） / **8443**（HTTPS, `server-https.js`） |
| **Whisper サーバー** | whisper.cpp `whisper-server`、multipart で音声を受け JSON でテキストを返す | **8080** |
| **SBV2（TTS）** | Style-Bert-VITS2 の FastAPI | **8765** |

起動補助: `ops/audioio/start-whisper.ps1`、`ops/audioio/start-sbv2.ps1`。

---

## 3. 仕様（要件）

### 3.1 VAD アーキテクチャ（サーバーサイド）

VAD（Voice Activity Detection）は **voice-bridge サーバー側** で行う。  
クライアントは **16kHz mono PCM16 WAV** を連続的に送信し続けるだけでよい。  
発話区間の検出・確定タイミングの判断はすべてサーバーが担う。

| 項目 | 要件 |
|------|------|
| **モデル** | Silero VAD（`@ricky0123/vad-node`）、起動時に 1 回ロード |
| **フレーム** | 1536 samples = 96ms @ 16kHz |
| **発話開始** | `positiveSpeechThreshold: 0.5` |
| **発話終了** | 768ms の沈黙（`redemptionFrames: 8`） |
| **誤検知除去** | 288ms 未満の発話は無視（`minSpeechFrames: 3`） |
| **同時接続** | 1 接続のみ（`frameProcessor` を共有・接続ごとに reset） |

### 3.2 暫定（draft）と確定（final）

| 項目 | 要件 |
|------|------|
| **暫定** | 発話中、**2 秒ごと**に蓄積フレームを Whisper に送り `draft` を返す |
| **確定** | VAD が発話終了を検出したとき、発話全体の音声を Whisper に送り `final` を返す |
| **busy 中** | 確定処理中に次の発話が届いても `busy` フラグで排他制御（処理をキュー・上書きしない） |

### 3.3 クライアント → サーバー（WebSocket）

| 種別 | 内容 |
|------|------|
| **バイナリ** | **16kHz mono PCM16 WAV**（RIFF ヘッダ付き）を連続送信 |
| JSON `config` | `{ "type": "config", "mimeType": "..." }` — 後方互換のため受け付けるが no-op |
| JSON `vad` | `{ "type": "vad", "speaking": true/false }` — 後方互換、no-op |
| JSON `final_pending` | 後方互換、no-op |

> クライアントは **バイナリを送り続けるだけ**でよい。JSON メッセージは不要。

### 3.4 サーバー → クライアント（WebSocket）

| type | ペイロード | 意味 |
|------|-----------|------|
| `speech_start` | `{ "type": "speech_start" }` | VAD が発話開始を検出 |
| `draft` | `{ "type": "draft", "text": "..." }` | 発話中の暫定テキスト（2 秒ごと） |
| `final` | `{ "type": "final", "text": "..." }` | 発話確定テキスト |
| `reply_reset` | `{ "type": "reply_reset" }` | 返答エリアのリセット |
| `reply_delta` | `{ "type": "reply_delta", "text": "..." }` | 返答の追記 |
| `error` | `{ "type": "error", "text": "..." }` | 制御メッセージのエラーのみ（音声エラーはログのみ） |

### 3.5 HTTP（voice-bridge）

| 要件 | 内容 |
|------|------|
| ヘルス | `GET /health` → `{ "ok": true }` |
| 静的ファイル | `public/`（例: `index.html`） |
| rnnoise | `GET /rnnoise-sync.js` — RNNoise WASM をパッチして配信 |

### 3.6 Whisper（HTTP）

| 要件 | 内容 |
|------|------|
| エンドポイント | `POST /inference`（whisper.cpp 標準） |
| リクエスト | `multipart/form-data`、フィールド名 **`file`**、`response_format=json` |
| レスポンス | JSON `{ "text": "..." }` |
| 接続先 | 環境変数 **`WHISPER_URL`**（未設定時: `http://127.0.0.1:8080/inference`） |

### 3.7 音声の最小単位

| 要件 | 内容 |
|------|------|
| `MIN_AUDIO_BYTES = 256` | これ未満のバッファは Whisper を呼ばず空文字を返す |

### 3.8 TTS / SBV2

- Style-Bert-VITS2 の FastAPI が REST を提供（`:8765`）。
- **現状の voice-bridge は TTS を呼ばない**。確定後の処理は `streamReply`（プレースホルダ）で差し替え可能。

## 4. 実装仕様（現行コード）

### 4.1 実装ファイル一覧

| パス | 内容 |
|------|------|
| `webui/voice-bridge/server.js` | HTTP 8090、WebSocket `/ws`、サーバーサイド VAD、Whisper プロキシ |
| `webui/voice-bridge/server-https.js` | HTTPS 8443（同一ロジック） |
| `webui/voice-bridge/public/index.html` | 録音・WAV 送信 UI |
| `ops/audioio/start-whisper.ps1` | whisper-server 起動 |

### 4.2 voice-bridge（`server.js`）

#### VAD 初期化

```
initVAD() → NonRealTimeVAD.new({ ... }) → sharedVad
```

起動時に 1 回だけ呼ぶ。完了してから `server.listen()` する。

#### 接続ごとの状態

| 変数 | 型 | 意味 |
|------|-----|------|
| `fp` | frameProcessor | sharedVad.frameProcessor（接続時 reset） |
| `isSpeaking` | bool | 発話中フラグ |
| `speechChunks` | Float32Array[] | 発話中フレーム（draft 用） |
| `pcmRemainder` | Float32Array | フレーム境界の端数バッファ |
| `draftTimer` | timer | 2 秒ごとの draft 送信タイマー |
| `busy` | bool | 確定 Whisper 処理中フラグ |

#### バイナリ受信フロー

```
バイナリ受信
  → parseWavPcm16()  ← RIFF 検出・PCM16 抽出
  → pcm16ToFloat32()
  → processFrames()
      ├─ 端数バッファと結合
      ├─ 1536 sample ずつ fp.process(frame)
      │     ├─ SpeechStart → isSpeaking=true, draftTimer 開始, send(speech_start)
      │     ├─ （中間）    → speechChunks に追加
      │     └─ SpeechEnd  → handleSpeechEnd(audio)
      └─ 端数を pcmRemainder に保存
```

#### draft タイマー（`DRAFT_INTERVAL_MS = 2000ms`）

発話中に 2 秒ごとに `speechChunks` のスナップショットを Whisper に送り `draft` を返す。

#### `handleSpeechEnd(audioFloat32)`

```
draftTimer 停止
isSpeaking = false
busy でなければ:
  float32ToWav(audio) → transcribeBuffer() → send({ type: 'final', text })
  → streamReply()（プレースホルダ）
```

#### `transcribeBuffer(buffer)`

| 項目 | 実装 |
|------|------|
| 最小サイズ | 256 バイト未満は空文字を即返す |
| multipart | `file=audio.wav`、`response_format=json` |
| HTTP エラー | warn ログし空文字（クライアントへ `error` は送らない） |
| 例外 | warn ログし空文字 |

#### `streamReply(finalText, send)`（プレースホルダ）

`reply_reset` → `了解です。${finalText}` を 1 文字ずつ `reply_delta`（8ms 間隔）。

### 4.3 WAV ユーティリティ

| 関数 | 役割 |
|------|------|
| `parseWavPcm16(buf)` | RIFF ヘッダを解析し `{ pcm16, sampleRate }` を返す |
| `pcm16ToFloat32(pcm16)` | Int16Array → Float32Array（÷ 32768） |
| `float32ToWav(float32)` | Float32Array → 16kHz mono WAV Buffer（Whisper 送信用） |
| `concatFloat32(arrays)` | Float32Array[] を結合 |

### 4.4 Whisper 起動（`ops/audioio/start-whisper.ps1`）

詳細は **[Whisper実装仕様.md](./Whisper実装仕様.md)** を参照。

| 項目 | 値 |
|------|-----|
| ポート | 8080、`0.0.0.0` バインド |
| モデル | `models\ggml-base.bin` |
| 固定引数 | `-l ja`、`--convert`、`--split-on-word` |
| 高速化 | `REN_WHISPER_FAST=1` → `-bo 1 -nf`、`REN_WHISPER_FLASH_ATTN=1` → `-fa` |
| 排他 | グローバルミューテックス + ポート確認で二重起動抑止 |

## 7. 別 PC への分離

### 7.1 ネットワーク

- voice-bridge から各サービスへ TCP で到達できること。
- ファイアウォールで Whisper（:8080）と SBV2（:8765）のポートを開けるか、逆プロキシで集約。

### 7.2 設定の外部化

| 項目 | 環境変数 | 状態 |
|------|----------|------|
| Whisper URL | `WHISPER_URL` | voice-bridge 対応済み |
| TTS URL | `TTS_BASE_URL`（予定） | 未実装 |

### 7.3 論理アーキテクチャ（分離時）

```
[ブラウザ] --WSS/HTTPS--> [voice-bridge :8090/:8443]
                              |-- HTTP --> [Whisper PC :8080]
                              |-- HTTP --> [SBV2 PC :8765]   （TTS 実装後）
```

## 9. 今後の拡張（メモ）

- 確定テキスト → **LLM** → **SBV2 `/synthesis`** までのパイプラインを voice-bridge または別サービスに実装。
- `streamReply` を実際の LLM + TTS 呼び出しに差し替え。
- `TTS_BASE_URL` 環境変数と voice-bridge からの TTS 呼び出し実装。
- 複数同時接続が必要になった場合は `NonRealTimeVAD.new()` を接続ごとに生成する。
