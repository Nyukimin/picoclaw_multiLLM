# STT/TTS 接続基本事項

## 1. 基本方針

RenCrow における音声入出力の基本事項を以下に定義する。

- STT は **必ず Chat サーバ経由**で STT サーバに接続する
- TTS は **必ず Chat サーバ経由**で TTS サーバに接続する
- ブラウザやクライアントが STT/TTS サーバへ直接接続する構成は、検証用途を除き採用しない

## 2. 標準接続経路

```text
[Client / Browser]
    -> [Chat Server]
        -> [STT Server (Whisper)]
        -> [TTS Server (SBV2 等)]
```

## 3. 目的

- 接続先と契約を Chat サーバで集約し、クライアント実装を単純化する
- 認証、監査ログ、リトライ、タイムアウト、フォールバックの制御点を一元化する
- STT/TTS サーバ差し替え時の影響範囲を Chat サーバ内に閉じ込める

## 4. 運用ルール

- STT 接続先は Chat サーバ側設定（例: `WHISPER_URL`）で管理する
- TTS 接続先は Chat サーバ側設定（例: `tts.*` 設定群）で管理する
- サーバ間通信の契約変更は、先に Chat サーバのアダプタ契約を更新してからクライアントへ公開する

## 5. 適用範囲

本方針は `docs/STT` に記載する STT 関連仕様の上位基本事項として扱う。  
TTS 詳細仕様は `docs/12_SBV2_TTS_現状仕様.md` を参照し、同方針に従って更新する。
