# 他のブラウザ・他の PC から SBV2（server_editor）を呼ぶ

## 状況別

### 1. 同じ PC の別ブラウザで `http://127.0.0.1:8000` を開く

- **そのまま利用可能**（同一オリジン）。Editor の静的 UI も API も同じホスト。
- `http://localhost:8000` も同様。

### 2. 同じ PC で「別ポートのページ」（例: `http://localhost:5173`）から `fetch` で API を叩く

- ページのオリジン（`http://localhost:5173`）が **許可リストに無いと CORS で失敗**する。
- 対処: 下記「CORS を広げる」または「自前のプロキシ経由」。

### 3. 別 PC のブラウザから `http://<SBV2のLAN IP>:8000` で開く／`fetch` する

- **到達性**: `uvicorn` は `host=0.0.0.0` のため、**SBV2 マシンの Windows ファイアウォールで TCP 8000 を許可**すれば LAN からは届く。
- **CORS**: 別 PC のページは `http://192.168.x.x:ポート` などになるため、**既定の `origins` ではブロック**される。

### 4. **HTTPS** のページから **HTTP** の SBV2 を呼ぶ

- ブラウザの **Mixed Content** でブロックされやすい。
- 対処: SBV2 前に **HTTPS のリバースプロキシ**を置く、または **ページも HTTP（開発のみ）**に揃える。

---

## 対処パターン（推奨順）

### A. 開発向け: SBV2 側の CORS を拡張する（最も単純）

`devices/SBV2/Style-Bert-VITS2/server_editor.py` の `origins` に、**実際にページを出しているオリジン**を追加する。

例（フロントを `http://192.168.1.10:3000` で出す場合）:

```python
origins = [
    "http://localhost:3000",
    "http://localhost:8000",
    "http://127.0.0.1:3000",
    "http://127.0.0.1:8000",
    "http://192.168.1.10:3000",
]
```

**注意**: 本番で `["*"]` にするのは避け、必要なオリジンだけに限定する。

### B. 本番に近い: 同一オリジンのバックエンド経由（プロキシ）

- ブラウザは **`https://あなたのドメイン/api/...`** だけにアクセス。
- **nginx / Caddy / Node（voice-bridge 等）**が SBV2（`http://127.0.0.1:8000`）へ中継。
- ブラウザから見るオリジンはフロントと同じになるため **CORS 問題を回避しやすい**（API を同じドメインのパスにマウントする場合）。

### C. Tailscale 等の名前解決で叩く場合

- クライアントの **ページのオリジン**（例: `https://machine.ts.net:3000`）を **`origins` に追加**するか、**B と同様にプロキシ**する。
- **HTTPS ページ → HTTP SBV2** は Mixed Content のため、**HTTPS で SBV2 手前を終端**する構成が安全。

---

## まとめ

| やりたいこと | 最低限必要なこと |
|--------------|------------------|
| 別ブラウザで同じマシンの UI を開く | `http://127.0.0.1:8000` にアクセス |
| 別 PC から UI/API にアクセス | ファイアウォール開放 + **CORS に相手オリジンを追加**、または **プロキシ** |
| 別アプリの Web ページから `fetch` | **`origins` にそのページのオリジン**、または **同一オリジンのプロキシ** |

一次情報: `server_editor.py` の `CORSMiddleware` と `origins` リスト。
