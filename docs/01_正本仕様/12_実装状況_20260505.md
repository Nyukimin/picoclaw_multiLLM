最新追加仕様は「記憶OSつきマルチキャラクター会話基盤」を目標にしているが、現行実装はまだ Go 製の既存 RenCrow v5 系アーキテクチャが中心である。

## 1. 全体評価

現行実装は、以下の基盤がすでにある。

- Go製の `MessageOrchestrator`
- Mio / Shiro / Coder1〜4 のエージェント構造
- Viewer
- IdleChat
- TTS / STT 連携
- ConversationEngine / RecallPack
- Redis / DuckDB / Qdrant 想定の会話記憶
- RSS由来のGlossary / IdleChatトピック
- Coder Persona / LightMemory
- MLX / OpenAI互換ローカルLLM接続
- `Chat` / `Worker` / `Wild` model alias
- local LLM timeout / warmup / concurrency 制御
- SQLite L1 hot store の会話イベント保存
- L1記憶状態管理
- L1 Search Cache
- Search Cache の RecallPack 注入
- Mio Web検索の cache-first / miss時保存
- L1 staging schema
- L1 staging validator
- L1 staging promoter
- L1 Source Registry
- L1 News DB
- L1 Daily Digest

一方、2026-05-01 追加仕様で掲げた以下は未実装または未統合である。

- LangGraph 中心の会話ランタイム
- ルミナ / クラリス / ノクス体系
- Parquet cold archive
- Memory Inspector

## 5. 最新仕様との差分詳細

### 5.1 会話制御

最新仕様:

```text
User Input
  -> LangGraph Turn Controller
  -> Recall Orchestrator
  -> Persona Prompt Builder
  -> Local LLM
  -> Memory Candidate Extractor
  -> Staging / Validator
```

現行実装:

```text
User Input
  -> MessageOrchestrator
  -> Mio.DecideAction
  -> Mio.Chat / Shiro.Execute / Coder
  -> EventHub / Viewer / TTS
```

差分:

- LangGraphは未導入。
- Turn Controller / character subgraph は未実装。
- 既存のGoオーケストレーターに統合するか、LangGraphを別ランタイムとして接続するか未決定。

### 5.2 LLM接続

最新仕様:

- MLXローカルサーバ
- OpenAI互換API
- model名は `Chat` / `Worker` / `Wild`
- RenCrow側はMLX専用providerを新規実装しない

現行実装:

- Chat provider: `local_llm.enabled=true` なら OpenAI互換local provider、falseなら Ollama
- Worker provider: `local_llm.enabled=true` なら OpenAI互換local provider、falseなら Ollama
- Wild provider: `local_llm.enabled=true` なら OpenAI互換local providerとして生成
- Embedding / summarizer / profile extractor は Ollama 前提
- Coder provider は `deepseek/openai/claude/gemini/ollama`

差分:

- `cmd/picoclaw/main.go` の Chat/Worker主経路は `buildPrimaryLLMProviders()` 経由に変更済み。
- OpenAI互換ローカルproviderを Chat/Worker/Wild に差し込む `local_llm` 設定は実装済み。
- `local_llm.enabled=true` の場合、Ollama設定なしでも validation を通過する。
- Wild provider は生成されるが、通常ルーティングからWildを明示選択する導線は未実装。
- Embedding / summarizer / profile extractor はまだ Ollama 前提。

### 5.3 記憶

最新仕様:

| 層 | store |
|---|---|
| L0 | LangGraph checkpoint + rolling summary |
| L1 | SQLite WAL |
| L2 | DuckDB + Parquet |
| L3 | DuckDB + Parquet + vector sidecar |

現行実装:

| 層 | store |
|---|---|
| 短期 | Redis |
| L1 hot | SQLiteに会話イベントをミラー保存可能 |
| 中期 | DuckDB |
| 長期 | Qdrant想定VectorDB |

差分:

- SQLite hot store への保存とRedis miss時のRecall fallbackは実装済み。
- Parquet archive がない。
- L0/L1/L2/L3の名前と責務が未統合。
- `conv:<thread_id>` namespace はL1保存で導入済み。`user:` / `char:` / `kb:` は未実装。

### 5.4 外部取得

最新仕様:

```text
Source Registry
  -> Scheduler
  -> Fetcher
  -> Staging
  -> Validator
  -> Promoter
  -> Official DB
```

現行実装:

- RSS parser はある。
- Glossary / IdleChat 用途で使っている。
- validator / promoter はない。

差分:

- 外部取得データを正式DBに入れる前の検証層がない。
- raw_text と summary_draft の分離仕様が未実装。
- Source Registry がない。

## 8. 現時点の結論

現行実装は、RenCrow v5系の Go 実装としてはかなり進んでいる。
特に、Viewer、IdleChat、TTS同期、ConversationEngine、Coder構造は既に土台がある。

2026-05-01 の最新追加仕様のうち、LLM接続まわりは実装が進んだ。
`local_llm.enabled=true` により、MLX / OpenAI互換ローカルサーバへ `Chat` / `Worker` / `Wild` alias で接続できる。
timeout、warmup、concurrency制御も追加済みである。

次に進めるべきことは、記憶OSの土台である。

```text
完了/部分完了:
- SQLite L1 hot store
- L1 Recall fallback
- observed / candidate / confirmed state
- Search Cache store
- Search Cache RecallPack注入
- Mio Web検索 cache-first / miss時保存
- ToolRunner web_search cache hook/main配線
- L1 Event Log store
- message/search cache/state update event auto logging

次の優先:
1. Event LogのViewer表示
2. `user:` / `char:` / `kb:` の明示UI/validator連携
3. observed / candidate / confirmed の明示昇格UIとvalidator連携
4. staging schema
5. validator / promoter
6. RecallPack L0/L1/L2/L3
```

ここを固めると、News DB、Knowledge DB、Memory Inspector を破綻しにくく追加できる。
