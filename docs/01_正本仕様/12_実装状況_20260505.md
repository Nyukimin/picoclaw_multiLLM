# RenCrow 実装状況メモ

**作成日**: 2026-05-05
**対象**: 現行リポジトリ実装と 2026-05-01 追加仕様の差分
**参照仕様**: `docs/01_正本仕様/11_追加仕様_20260501_記憶OS構想.md`

この文書は、現時点の実装状況を一覧化したメモである。
最新追加仕様は「記憶OSつきマルチキャラクター会話基盤」を目標にしているが、現行実装はまだ Go 製の既存 RenCrow v5 系アーキテクチャが中心である。

## 1. 全体評価

現行実装は、以下の基盤がすでにある。

- Go製の `MessageOrchestrator`
- Mio / Shiro / Coder1〜4 のエージェント構造
- Viewer
- IdleChat
- TTS / STT 連携
- ConversationEngine / RecallPack
- Redis / DuckDB / Qdrant 想定の会話記憶
- RSS由来のGlossary / IdleChatトピック
- Coder Persona / LightMemory

一方、2026-05-01 追加仕様で掲げた以下は未実装または未統合である。

- LangGraph 中心の会話ランタイム
- ルミナ / クラリス / ノクス体系
- MLX OpenAI互換ローカルproviderを主経路にする実装
- `Chat` / `Worker` / `Wild` model alias routing
- SQLite hot store
- Parquet cold archive
- Source Registry
- staging / validator / promoter
- News DB / Daily Digest
- Search Cache
- Memory Inspector

## 5. 最新仕様との差分詳細

### 5.1 会話制御

最新仕様:

```text
User Input
  -> LangGraph Turn Controller
  -> Recall Orchestrator
  -> Persona Prompt Builder
  -> Local LLM
  -> Memory Candidate Extractor
  -> Staging / Validator
```

現行実装:

```text
User Input
  -> MessageOrchestrator
  -> Mio.DecideAction
  -> Mio.Chat / Shiro.Execute / Coder
  -> EventHub / Viewer / TTS
```

差分:

- LangGraphは未導入。
- Turn Controller / character subgraph は未実装。
- 既存のGoオーケストレーターに統合するか、LangGraphを別ランタイムとして接続するか未決定。

### 5.2 LLM接続

最新仕様:

- MLXローカルサーバ
- OpenAI互換API
- model名は `Chat` / `Worker` / `Wild`
- RenCrow側はMLX専用providerを新規実装しない

現行実装:

- Chat provider: Ollama
- Worker provider: Ollama
- Embedding / summarizer / profile extractor も Ollama 前提
- Coder provider は `deepseek/openai/claude/gemini/ollama`

差分:

- `cmd/picoclaw/main.go` の Chat/Worker主経路が `ollama.NewOllamaProviderWithNumCtx()` 固定。
- OpenAI互換ローカルproviderを Chat/Worker/Wild に差し込む設定がない。
- config validation も `ollama.base_url` / `ollama.model` 必須。

### 5.3 記憶

最新仕様:

| 層 | store |
|---|---|
| L0 | LangGraph checkpoint + rolling summary |
| L1 | SQLite WAL |
| L2 | DuckDB + Parquet |
| L3 | DuckDB + Parquet + vector sidecar |

現行実装:

| 層 | store |
|---|---|
| 短期 | Redis |
| 中期 | DuckDB |
| 長期 | Qdrant想定VectorDB |

差分:

- SQLite hot store ではない。
- Parquet archive がない。
- L0/L1/L2/L3の名前と責務が未統合。
- namespace設計が未実装。

### 5.4 外部取得

最新仕様:

```text
Source Registry
  -> Scheduler
  -> Fetcher
  -> Staging
  -> Validator
  -> Promoter
  -> Official DB
```

現行実装:

- RSS parser はある。
- Glossary / IdleChat 用途で使っている。
- validator / promoter はない。

差分:

- 外部取得データを正式DBに入れる前の検証層がない。
- raw_text と summary_draft の分離仕様が未実装。
- Source Registry がない。

### 5.5 UI

最新仕様:

- 3Dキャラ表示
- キャラバッジ
- スピーチキュー
- Memory Inspector
- ニュースパック表示
- 参照表示
- thumbs score

現行実装:

- Viewer はある。
- Ops / Overview / Progress / Chat Timeline / System / IdleChat / Sessions / Jobs がある。
- IdleChatには `Live Timeline / Summary Review / History` がある。

差分:

- 記憶OS向けUIは未実装。
- キャラ指名UIやMemory Inspectorはない。

### Phase B: LLM接続

## 8. 現時点の結論

現行実装は、RenCrow v5系の Go 実装としてはかなり進んでいる。
特に、Viewer、IdleChat、TTS同期、ConversationEngine、Coder構造は既に土台がある。

ただし、2026-05-01 の最新追加仕様は、まだ設計構想に近い。
特に LangGraph、SQLite hot store、staging/validator、MLX alias routing、記憶namespace は未実装である。

最初に進めるべきことは、コード変更ではなく以下の仕様統合である。

```text
1. キャラ名体系
2. LLM alias体系
3. hot store 方針
4. LangGraph採用方針
5. staging/validator の境界
```

ここを固定すると、以後の実装順序を安全に決められる。
