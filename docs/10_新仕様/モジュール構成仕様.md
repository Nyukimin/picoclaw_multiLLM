# モジュール構成仕様

## 全体構成

RenCrow は Clean Architecture 風の構成を維持する。

```text
cmd/picoclaw
  起動、CLI、composition root、runtime wiring、HTTP server

internal/adapter
  Viewer、channel、health、entry、config など外部入出力

internal/application
  orchestration、Worker execution、IdleChat、sourcefetcher、TTS coordination

internal/domain
  routing、task、proposal、patch、session、execution、transport などの契約

internal/infrastructure
  LLM provider、persistence、transport、tools、security、STT/TTS、VTuber
```

## 仕様変更時の実装箇所対応

仕様変更を行うときは、最初に「どの仕様を変えるのか」と「主にどの実装箇所を触るのか」を対応させる。

仕様と実装箇所が 1 対 1 に説明できない場合は、次のどちらかとして扱う。

- 仕様の境界が粗く、複数仕様を同時に変更しようとしている。
- モジュール分割または実装配置が悪く、責務が漏れている。

この状態で実装を進めない。先に仕様単位を分けるか、interface、contract、DTO、event、adapter、repository、provider 境界を整理する。

### 対応が崩れたときの扱い

- 1 つの仕様変更で 3 つ以上の主担当パッケージを同時に変更する場合は、仕様を分割する。
- 仕様に対する主担当が `cmd/picoclaw` だけになる場合は、Application / Adapter / Infrastructure へ分離できないか確認する。
- `helper`、`util`、`manager`、`service` という名前で責務を吸収する前に、入力、出力、副作用、永続化、ログ、エラー契約を明文化する。
- テストだけが仕様の置き場所になっている場合は、`docs/10_新仕様/` または正本仕様へ仕様文を追加する。
- 実装箇所が対応表と違う場合は、実装前に対応表を更新し、差分理由を残す。

## `cmd/picoclaw`

`cmd/picoclaw` は application の起動と composition root を担当する。業務ロジックや usecase の本体を増やさない。

### `main.go`

責務:

- CLI entrypoint
- config load
- top-level runtime assembly
- HTTP server startup
- registration / factory / wiring の呼び出し

置かないもの:

- 長い route registration 本体
- handler 実装の詳細
- provider 固有の詳細
- Viewer / IdleChat / STT / TTS の業務判断

### `routes.go`

責務:

- HTTP route registration
- route path と handler 接続の対応

主な分類:

- channel webhook routes
- Viewer static / runtime routes
- LLM Ops routes
- STT / audio routes
- Viewer monitor / evidence / memory / source registry routes
- entry / chrome routes
- IdleChat routes
- health routes

### `runtime_dependencies.go`

責務:

- orchestrator、stores、Viewer handlers、IdleChat、TTS/STT runtime などの依存組み立て
- Application / Adapter / Infrastructure の接続

注意:

- runtime wiring と usecase 本体を混ぜない。
- live runtime config と repo example を混同しない。

### `runtime_local_agents.go`

責務:

- distributed local agent runtime
- local worker / coder agent loop
- local transport response delivery
- SSH transport registration helper
- distributed agent availability helper

置かないもの:

- DistributedOrchestrator の usecase 本体
- WorkerExecutionService の実行詳細
- Coder proposal 生成の内部実装

### `runtime_idlechat_handlers.go`

責務:

- IdleChat HTTP handler wiring
- IdleChat start / stop / status / forecast / story / logs endpoint
- IdleChat 起動前の LLM Ops start gate

置かないもの:

- IdleChat orchestration 本体
- Viewer JS / CSS
- TTS provider 実装

### runtime option assembly

責務:

- debug / display / runtime option assembly
- Viewer runtime config に渡す表示用 option の整理

現行実装:

- `cmd/picoclaw/runtime_dependencies.go`
- `cmd/picoclaw/routes.go`
- `cmd/picoclaw/stt_runtime_factory.go`
- `cmd/picoclaw/llm_runtime_factory.go`
- `cmd/picoclaw/health_runtime.go`

`cmd/picoclaw/runtime_options.go` は現行ファイルではなく、将来の分離候補である。実装前に、Viewer runtime config、debug system options、LLM Ops options、STT stream URL の入力、出力、副作用、ログ、エラー契約を分けてから作成する。

### `health_runtime.go`

責務:

- health service builder
- local LLM health check builder
- execution stats / evidence summary loader
- TTS debug URL inference
- live service の状態確認に使う最小単位

### `health_commands.go`

責務:

- `health` CLI command
- `status` CLI command
- `doctor` CLI command
- CLI JSON / text 出力

置かないもの:

- HTTP handler 実装
- provider 起動制御
- LLM server の一般仕様化

### `stt_runtime_factory.go`

責務:

- STT runtime struct
- STT provider / handler / WebSocket handler の組み立て
- `/stt/health`、`/stt/file`、`/stt/chat-input` と互換 WebSocket route 登録の呼び出し

置かないもの:

- WebSocket relay 本体
- audio payload 変換
- HTTP inference
- URL inference の詳細

### `stt_runtime_config.go`

責務:

- STT provider URL / base URL / stream URL inference
- STT provider selection
- STT gateway URL resolution

### `stt_runtime_websocket.go`

責務:

- `/stt`、`/stt-ws`、`/ws` の互換 WebSocket route 登録
- STT WebSocket provider handler
- STT gateway proxy handler
- STT event / error frame serialization

### `stt_runtime_audio.go`

責務:

- STT final timeout / silence threshold
- PCM16 payload の WAV 化
- silence 判定

### `stt_runtime_http.go`

責務:

- 外部 HTTP STT inference
- adaptive timeout
- timeout error classification

## `internal/application/orchestrator`

### MessageOrchestrator

MessageOrchestrator は通常メッセージ処理の top-level orchestration を担当する。

構成:

- `message_orchestrator.go`
  - top-level orchestration
- `message_orchestrator_routes.go`
  - route dispatch
- `message_orchestrator_routing.go`
  - routing decision
- `message_orchestrator_response.go`
  - response assembly
- `message_orchestrator_session.go`
  - session lifecycle
- `message_orchestrator_task.go`
  - task context builder
- `message_orchestrator_tts_lifecycle.go`
  - TTS lifecycle
- `message_orchestrator_events.go`
  - event emitter port
- `message_orchestrator_idle.go`
  - IdleChat entry
- `message_orchestrator_autonomous.go`
  - autonomous route handling

守る契約:

- routing decision の後に route dispatch する。
- Chat route は Worker / Coder 実行責務を持たない。
- Worker error、generate error、unknown route を成功 response に変換しない。
- event、response、session、report の整合を保つ。

### CodeExecutor

CodeExecutor は Coder / Worker 境界を担当する。

構成:

- `code_executor.go`
  - entry と基本構造
- `code_executor_selection.go`
  - coder selection
- `code_executor_proposal.go`
  - proposal path
- `code_executor_generate.go`
  - generate path
- `code_executor_events.go`
  - event helper
- `code_executor_response.go`
  - response helper

守る契約:

- Coder は plan / patch / proposal 生成に留まる。
- Worker が実行主体である。
- invalid proposal は Worker に到達させない。
- Worker execution error を fallback 成功へ変換しない。

DistributedOrchestrator は分散実行の orchestration を担当する。

構成:

- `distributed_orchestrator.go`

- `distributed_orchestrator_runtime.go`
  - transport mode、message context、distributed timeout helper
- `distributed_orchestrator_retry.go`
  - coder retry instruction、distributed execution error classification
- `distributed_orchestrator_display.go`
  - route notice、agent display name
- `distributed_orchestrator_events.go`
  - event emission
- `distributed_orchestrator_evidence.go`
  - execution report / evidence
- `distributed_orchestrator_tts_lifecycle.go`
  - TTS lifecycle
- `distributed_orchestrator_session.go`
  - distributed session lifecycle
- `distributed_orchestrator_autonomous.go`
  - autonomous coordinator
- `distributed_orchestrator_routes.go`
  - route dispatcher
- `distributed_orchestrator_transport.go`
  - transport executor
- `distributed_orchestrator_code.go`
  - code execution
- `distributed_orchestrator_coder_selection.go`
  - coder selection
- `distributed_orchestrator_attribution.go`
  - attribution guard

守る契約:

- local / ssh / mailbox / direct / distributed transport の error contract を維持する。
- 接続不能な coder / transport を成功扱いしない。
- evidence、event、session を落とさない。
- attribution guard は user request と agent response を混同しない。

## Viewer / IdleChat / Audio

Viewer は単なる静的 UI ではなく、runtime config、SSE、event log、memory/source registry、IdleChat、STT/TTS の観測面である。

守る境界:

- 表示本文は表示用 event / state を主たる入力とする。
- TTS chunk は音声再生と口パク trigger の入力であり、表示本文の唯一根拠にしない。
- IdleChat は raw response、view data、audio trigger を分ける。
- STT input は通常 chat のみに流し、IdleChat には流さない。
- audio、lipsync、log は別の観測対象として扱う。

## Memory / Source Registry

Memory / Source Registry は、状態遷移を飛ばさないことを最重要契約とする。

守る境界:

- observed
- candidate
- validated
- promoted

保存、stage、validate、promote は別フェーズとして扱い、直接 confirmed / pinned 相当へ昇格しない。

## LLM provider / runtime config

provider factory、middleware、runtime config、Viewer LLM ops は分けて考える。

守る境界:

- repo example は実行中の設定ではない。
- live runtime config は `~/.picoclaw/config.yaml` と実 service で確認する。
- Viewer runtime config は表示用の観測面であり、正本仕様そのものではない。
- provider 固有仕様を Application / Domain へ漏らさない。
