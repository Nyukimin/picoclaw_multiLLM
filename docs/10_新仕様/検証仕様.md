# 検証仕様

## 目的

この文書は、リファクタリング後の RenCrow を検証するための標準コマンド、テスト分類、外部依存の扱いを定義する。

## 標準テスト

通常の変更後は、次を実行する。

```bash
GOCACHE=/tmp/picoclaw-gocache go test ./...
```

cache を避けて再確認する場合:

```bash
GOCACHE=/tmp/picoclaw-gocache go test -count=1 ./...
```

## E2E テスト

`test/e2e` は build tag `e2e` 付きで実行する。

```bash
GOCACHE=/tmp/picoclaw-gocache go test -tags=e2e ./test/e2e
```

cache を避けて再確認する場合:

```bash
GOCACHE=/tmp/picoclaw-gocache go test -count=1 -tags=e2e ./test/e2e
```

## live runtime E2E

live service の `/health` と `/viewer/runtime-config` を確認する場合:

```bash
PICOCLAW_LIVE_E2E=1 \
GOCACHE=/tmp/picoclaw-gocache \
go test -count=1 -tags=e2e ./test/e2e \
  -run TestE2E_Phase25LiveRuntimeHealthAndViewerConfig -v
```

確認対象:

- `http://127.0.0.1:18790/health`
- `http://127.0.0.1:18790/viewer/runtime-config`
- `local_llm`
- `stt_stream_url`

## browser Viewer E2E

Playwright で live Viewer を確認する場合:

```bash
PICOCLAW_BROWSER_E2E=1 \
PICOCLAW_LIVE_BASE_URL=http://127.0.0.1:18790 \
GOCACHE=/tmp/picoclaw-gocache \
go test -count=1 -tags=e2e ./test/e2e \
  -run TestE2E_Phase25BrowserViewerSessionContract -v
```

確認対象:

- Viewer が開けること。
- `#inp` に入力できること。
- `/viewer/send` が成功すること。
- 送信メッセージが Viewer 表示または Ops log に反映されること。
- 通常 Chat、IdleChat、TTS、口パク、ログの DOM 境界が存在すること。

## Phase25 で追加された主要テスト

- `test/e2e/phase25_routing_contract_test.go`
  - `/code`, `/code1`, `/code2`, `/code3` の explicit route contract。
- `test/e2e/phase25_live_runtime_contract_test.go`
  - live `/health` と Viewer runtime config。
- `test/e2e/phase25_browser_viewer_test.go`
  - browser Viewer session。
- `internal/adapter/config/config_example_contract_test.go`
  - repo example config の読み込み契約。
- `internal/adapter/viewer/viewer_static_contract_test.go`
  - Viewer 表示、音声、口パク、ログ、Memory / Source Registry の DOM 境界。

## 外部依存の扱い

次は、環境未準備時に skip される。

- Claude / DeepSeek / OpenAI / Gemini API key
- Google Search API key / CSE
- Ollama endpoint
- local_openai endpoint
- STT server
- TTS server
- browser permission / HTTPS
- SSH agent
- VTube Studio / audio device

skip は成功扱いではない。外部依存が未準備であることの記録として扱う。

## Viewer / IdleChat / Audio 検証

Viewer / IdleChat / Audio では、DOM 存在だけで完了扱いしない。

最低 1 session で次を確認する。

- 入力
- route
- response
- SSE event
- Viewer event log
- history / session state
- error / invalid response 表示
- TTS audio trigger
- lipsync trigger
- 終了状態

## 完了報告に含めるもの

- 実行したテストコマンド。
- 成功した検証。
- skip された外部依存。
- live service を見たかどうか。
- browser E2E を実行したかどうか。
- 残る外部依存リスク。
