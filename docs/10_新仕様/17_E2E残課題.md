# E2E 残課題

## 1. この文書の目的

この文書は、現時点で残っている E2E 確認の未完了項目を記録する。

単体テスト、handler test、stub test、local-only test の成功だけでは E2E 完了扱いにしない。外部依存が未準備で skip された項目、実 API / 実機分散 / 実ブラウザで未確認の項目は、環境未準備または未確認として扱う。

## 4. 次に実行する確認コマンド

ローカル live service が起動済みの場合:

```bash

GOCACHE=/tmp/picoclaw-gocache go test -v -count=1 -tags=e2e ./test/e2e
```

外部依存を含める場合は、対象 provider / Google Search / Ollama / channel adapter の実環境を準備してから実行する。

## 5. 判定ルール

- skip は成功ではなく、環境未準備または未確認として扱う。
- fallback は成功ではなく、期待 route 不成立として扱う。
- health ok だけで user flow 成立扱いにしない。
- handler / stub / unit test の成功だけで実 API E2E 完了扱いにしない。
- 実ブラウザ UI は、DOM 存在ではなく visible state と実操作の成立で判定する。
- docs の状態表を更新する場合は、E2E の確認範囲と skip 理由を併記する。
