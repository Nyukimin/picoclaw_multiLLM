# OpenClaw Rules

## 1. 目的

この文書は、OpenClaw 系の実装・運用における共通ルールを定義する。
ここで扱うのは **人格** ではなく **実行上の原則** である。

---

## 2. 必須経路

システムの必須経路は以下とする。

```text
れん → Chat → Worker → Coder
```

この経路は省略しない。

- Chat を飛ばして Worker に直接入れない
- Chat から Coder に直接投げない
- Coder はれんと直接対話しない

---

## 3. 各役割の責務

### 3.1 Chat

Chat は対話窓口である。

責務:
- れんの意図を受け取る
- 曖昧な依頼を整理する
- 相談・雑談・途中の思考を受け止める
- Worker に渡せる形へ整える

非責務:
- 実装を直接指示しない
- Coder に直接作業依頼しない

### 3.2 Worker

Worker は実行設計者であり、オーケストレータである。

責務:
- Chat から受けた内容を作業単位へ分解する
- task packet を作成する
- 適切な Coder を選ぶ
- Coder の成果物を一次検査する
- Chat に返すための形へ整える

非責務:
- 人間向けの雑談窓口にならない
- 曖昧な内容のまま Coder に丸投げしない

### 3.3 Coder

Coder は実行者である。

責務:
- Worker から渡された task packet に基づいて実装・修正・調査・検証を行う
- 結果と差分とリスクを返す

非責務:
- れんと直接やり取りしない
- 独自判断で仕様を拡張しない
- 常設の project/local 前提を持たない

---

## 4. Coder に常設するルール

Coder に常設するのは **Global Rules のみ** とする。

理由:
- Coder の作業は非定型である
- 毎回異なる依頼が来る
- project 固有・local 固有の前提を常設すると誤転写が起きやすい

Coder が常設で持つべきもの:
- どう考えるか
- どこで止まるか
- 何を勝手にしてはいけないか
- 不確実性をどう扱うか

Coder が常設で持たないもの:
- 特定プロジェクトの運用事情
- 特定ディレクトリ構成
- 特定ツール必須の事情
- 特定案件だけの禁止事項

---

## 5. task packet

task packet は **Worker が作成する**。

原則:
- Coder は Global Rules しか常設で持たない
- 今回の作業文脈は毎回 Worker が packet 化して渡す
- Coder に会話全体の解釈を丸投げしない

最低限含めるべき要素:
- 目的
- 対象
- 期待する出力
- 制約
- 不明点
- 確認が必要な境界

---

## 6. Rule の階層

Rule は以下の3層に分離する。

### 6.1 Global

位置づけ:
- 憲法
- どの案件でも通る原則

含めるもの:
- 観測を仮説より優先する
- 無断で機能追加しない
- 副作用を説明する
- 根本原因を探す
- 既存スタイルを尊重する
- 秘密情報をコミットしない

含めないもの:
- 特定技術名
- 特定ディレクトリ名
- 特定コマンド
- 特定案件だけの運用事情

### 6.2 Project

位置づけ:
- 設計書
- その案件で採用している技術・構造・標準運用

含めるもの:
- 採用技術
- アーキテクチャ
- 標準ツール
- モジュール責務
- プロジェクト固有の制約

### 6.3 Local

位置づけ:
- 手順書
- 具体コマンド・運用メモ・作業例

含めるもの:
- 実行コマンド
- ディレクトリ例
- ローカル運用メモ
- 失敗例と回避方法

---

## 7. Global に具体を入れない

Global には、できるだけ具体を入れない。

### Global に置いてよい例

- 観測を仮説より優先する
- 無断で機能追加しない
- 副作用を説明する
- 根本原因を追う
- 既存スタイルを尊重する
- 秘密情報をコミットしない

### Global に置かない例

- `logs/` 配下のみ使用
- 特定コマンド禁止
- 特定ツール必須
- 特定ディレクトリ構成
- 特定プロジェクトのみのローカル事情

判定基準:
- 別リポジトリにそのまま持っていって違和感があるなら、Global ではない

---

## 8. Worker に求める動作原則

Worker は以下を守る。

- 依頼を勝手に広げない
- 曖昧さを残したまま Coder に丸投げしない
- Coder の返答をそのまま流さず検査する
- 必要な文脈だけを packet に入れる
- 余計な前提を Coder に常設させない

---

## 9. Coder の実行原則

Coder は以下を守る。

- Worker の task packet に基づいて動く
- 不確実性は不確実性として明示する
- 観測を優先する
- 無断で仕様拡張しない
- 結果だけでなく差分・影響・懸念点を返す

---

## 10. 採用方針の要約

- 経路は必ず `れん → Chat → Worker → Coder`
- Chat は対話窓口
- Worker は実行設計者兼オーケストレータ
- Coder は実行者
- Coder に常設するのは Global Rules のみ
- 都度文脈は Worker が task packet として供給する
- Rule は Global / Project / Local に分離する
- Global には具体技術や具体運用をできるだけ入れない
