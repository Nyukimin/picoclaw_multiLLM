# 詳細実装仕様 01: 実行基盤とセキュリティ境界

**更新日**: 2026-03-19  
**ステータス**: 現行実装ベース  
**親仕様**: `docs/実装仕様_OpenClaw移植_v1.md`  

---

## 1. 概要

本仕様は、RenCrow における OpenClaw 互換の「安全に実行する」基盤を、現行コード準拠で整理したものである。  
中心となるのは次の 4 要素である。

1. `SecurityConfig` によるポリシー設定
2. `PolicyEngine` + `SandboxGuard` による deny/allow 判定
3. `PolicyRunner` + `execution.Service` による監査付きツール実行
4. `status / health / doctor` を含む運用 CLI

現行実装は `allow / deny` を中心としており、旧草案にあった `ask` 承認フローは入っていない。

---

## 2. 設定とドメイン面

### 2.1 SecurityConfig

**ファイル**: `internal/adapter/config/config.go`

```go
type SecurityConfig struct {
    Enabled           bool
    PolicyMode        string
    NetworkScope      string
    NetworkAllowlist  []string
    DenyCommands      []string
    WorkspaceEnforced bool
    Audit             SecurityAuditConfig
}

type SecurityAuditConfig struct {
    Enabled bool
    Backend string
    Path    string
}
```

主な意味:

- `policy_mode`: `strict | balanced | dev`
- `network_scope`: `blocked | allowlist | full`
- `deny_commands`: shell で拒否するシグネチャ
- `workspace_enforced`: workspace 外書き込み拒否
- `audit.backend`: 現行は `jsonl` が実用経路、`sqlite` は validation 上の選択肢

デフォルト:

- `security.audit.backend = jsonl`
- `security.audit.path = logs/execution_audit.jsonl`

### 2.2 実行レコード

**ファイル**: `internal/domain/execution/model.go`  
**ファイル**: `internal/domain/execution/report.go`

現行実装では 2 系統の記録を使い分ける。

- `domain/execution.Record`
  - tool 実行単位の policy / status / error を保持
  - `security.decision` または `security.violation` のイベント種別を持つ
- `domain/execution.ExecutionReport`
  - 実行結果の evidence
  - `job_id`, `goal`, `status`, `error_kind`, `verification`, `steps`, `created_at`, `finished_at` を持つ

前者は security / execution audit、後者は outcome evidence であり、役割が異なる。

## 3. セキュリティ境界の現行実装

### 3.1 PolicyEngine

**ファイル**: `internal/infrastructure/security/policy_engine.go`

`PolicyEngine.Evaluate(action)` は `execution.PolicyDecision` を返す。  
現行判定は次の順序で行う。

1. shell の禁止コマンドシグネチャ
   - `tool == "shell"`
   - `deny_commands` に部分一致したら `DecisionDeny`
2. workspace 外書き込み
   - `workspace_enforced == true`
   - `tool == "file_write"`
   - path が workspace 外なら `DecisionDeny`
3. ネットワーク制御
   - `web_search`, `http_request`, `fetch_url` を network tool とみなす
   - `blocked` なら deny
   - `allowlist` なら host 抽出と allowlist 照合
4. 上記以外は `DecisionAllow`

戻り値の `MatchedRuleID` 例:

- `deny.shell.signature`
- `deny.workspace.outside`
- `deny.network.blocked`
- `deny.network.host.missing`
- `deny.network.host.not_allowlisted`
- `allow.default`

### 3.2 SandboxGuard

**ファイル**: `internal/infrastructure/security/sandbox_guard.go`

現行 `SandboxGuard` の責務:

- `IsCommandDenied(command, denyCommands)`
- `IsPathWithinWorkspace(path, workspace)`
- `ExtractNetworkHost(args)`
- `IsHostAllowed(host, allowlist)`

特徴:

- path 判定は `filepath.Abs + filepath.Rel` で実装
- allowlist は完全一致と `.example.com` 形式の suffix 許容
- URL または `host` 引数から host を抽出できる

### 3.3 PolicyRunner

**ファイル**: `internal/infrastructure/security/policy_runner.go`

`PolicyRunner` は `tool.RunnerV2` をラップし、実行前に policy evaluation を挟む。

処理の流れ:

1. `ListTools()` で取得した metadata から tool 存在確認
2. `domainexecution.Action` を生成
3. `execution.Service.RequestToolExecution()` を呼ぶ
4. denied の場合は `tool.ErrPermissionDenied` を返す
5. allowed の場合は inner runner の結果を返す

`requestedBy` は `chat` または `worker` として注入される。

## 4. 実行監査と evidence

### 4.1 execution.Service

**ファイル**: `internal/application/execution/service.go`

`RequestToolExecution()` の流れ:

1. action を受領
2. `policy.Evaluate(action)`
3. `domain.Record` を生成
4. denied なら `StatusDenied` で保存して終了
5. allow なら `StatusRunning` で保存
6. 実 executor を呼ぶ
7. 成功なら `StatusSucceeded`
8. error なら `StatusFailed`

`TraceID` は現行実装では `job_id + ":" + action_id` で生成される。

### 4.2 監査ストア

**ファイル**: `internal/infrastructure/persistence/execution/`

現行の正本は JSONL である。

- `NewJSONLRepository(path)`
  - `domain.Record` の作成 / 更新 / 集計
- `NewJSONLReportStore(path)`
  - `ExecutionReport` の保存 / recent / job lookup

補足:

- audit path と evidence path は同一設定値から導出される場面がある
- Viewer の evidence は `ExecutionReport` 系を読む
- tool 単位の security audit と job 単位の evidence は完全には同一ではない

### 4.3 Viewer 監査要約

`/viewer/audit/summary` は monitor store 由来の件数要約を返す。  
これは CLI や JSONL 正本の代替ではなく、運用補助ビューである。

## 5. 実行系との接続

### 5.1 ToolRunner 保護

**ファイル**: `cmd/picoclaw/main.go`

`cfg.Security.Enabled` が true の場合:

1. `PolicyEngine` を構築
2. audit repository を JSONL で初期化
3. `chatToolRunnerV2` を `PolicyRunner` で wrap
4. `workerToolRunnerV2` を `PolicyRunner` で wrap

これにより Chat / Worker の tool 実行は同じ security policy を通る。

### 5.2 WorkerExecutionService

**ファイル**: `internal/application/service/worker_execution_service.go`

Worker の patch 実行系には別の実行境界があり、こちらも workspace と protected file を強く意識している。

主な防御:

- workspace 外 path の拒否
- protected file パターン判定
- shell / git / file edit の系統分離
- failure 分類
  - `security_error`
  - `timeout`
  - `proposal_invalid`
  - そのほか

つまり現行実装では、

- `PolicyRunner`: Tool 実行前の共通ポリシー
- `WorkerExecutionService`: patch/apply 系の個別防御

の二段構えになっている。

## 6. CLI 到達点

**ファイル**: `cmd/picoclaw/main.go`

現行 CLI で利用できる運用系コマンド:

- `picoclaw status`
- `picoclaw health`
- `picoclaw doctor`
- `picoclaw gateway status|restart`
- `picoclaw ollama status|restart`

到達点:

- `status`: 設定と主要コンポーネント状態の概要
- `health --json`: health report を JSON で返す
- `doctor`: 設定、audit path、health 状態をまとめて診断

旧草案の「最小追加予定」ではなく、これらはすでに本体 CLI に実装済みである。

## 7. OpenClaw 対応の現況

OpenClaw 観点との対応は次の通り。

| OpenClaw 観点 | 現行 RenCrow |
|---|---|
| Tools 実行前のポリシー評価 | `PolicyEngine` で実装済み |
| Sandbox / workspace 境界 | `SandboxGuard` と Worker 実行防御で実装済み |
| 監査ログ | JSONL audit + `ExecutionReport` で実装済み |
| 運用 CLI | `status / health / doctor` 実装済み |
| ask/approval フロー | 未実装 |
| 統一 gateway security モデル | 部分実装 |

---

## 8. 既知の制約

1. `PolicyDecision` は現行 `allow / deny` 中心で、`ask` 承認フローはない。
2. network policy は tool 名ベース判定であり、任意外部プロセスの全通信を網羅しているわけではない。
3. `file_write` 以外のファイル系ツールに対する workspace 強制は個別実装側にも依存する。
4. `security.audit.backend` は validation 上 `sqlite` を許容するが、現行主経路は JSONL である。
5. Viewer の audit summary は正本監査ストアそのものではなく、monitor 要約である。

---

## 9. 確認観点

- `cfg.Security.Enabled=true` で `PolicyRunner` が chat / worker に挿入される
- deny command が `tool.ErrPermissionDenied` になる
- workspace 外書き込みが deny される
- `security.audit.path` が書けない場合は `doctor` で検出できる
- `ExecutionReport` が Viewer evidence から見える

以上をもって、本仕様の対象は「実装進行中」ではなく、OpenClaw 由来の実行境界を RenCrow に適応した現行実装として扱う。
